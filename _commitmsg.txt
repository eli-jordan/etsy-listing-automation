fix(clients/printify): a product another shop holds is absent, not an error

`GET /v1/shops/{shop}/products/{id}.json` has four distinct failure shapes and
three of them mean "this shop does not have that product". `get_product` read
only the `404`, so the second one -- `400` with code 8104, "Product does not
belongs to shop #..." -- propagated as a `PrintifyApiError` and ended the
listing.

It is not a corner case. **Reconnecting a store changes the shop id**, and
every lockfile written against the old one then names a product the new shop
has never held. The workspace this was measured in was in exactly that state,
so the next `plan` would have failed where it should have re-created.

Read as absence **by code**, not by "any 400", so a genuine validation error
still raises rather than silently becoming a create -- which on this API means
a duplicate product, since `POST products.json` has no idempotency key and no
conflict (PRD 48).

api-findings.md gains the table of all four shapes, including the two whose
bodies carry neither `code` nor `errors.reason` and so surface as a raw JSON
blob -- a qualification on that document's claim that Printify's errors have
one shape.
