# Recolour a mockup template

Turns one blank mockup photo into the full Comfort Colors 1717 colour set: one recolour per garment colour, each generated by its own Codex delegate with ChatGPT's image model, all in parallel. The result is an export in exactly the shape [ingest-mockup-templates](../ingest-mockup-templates/SKILL.md) reads: `{scene} - {Colour}.png` paired with `{scene} - {Colour} - Text.png`, the colour-name overlay stored in this skill's `overlays/`.

`recolour.py` holds the 33 colour names and hex codes, writes the delegate briefs from [codex-brief.md](codex-brief.md), builds the pilot review, measures drift and assembles the export. Run it from the repo root in Cygwin zsh: `uv run python .claude/skills/create-mockup-template-cc1717/recolour.py {clean,prepare,pilot,drift,assemble} --help`.

Every photo the generator returns is smaller than 2048 and softer than a real photo, and each regeneration costs detail again. So the generator only ever supplies what had to change: `clean` keeps the original everywhere but the removed items, and `assemble` keeps the source everywhere but the shirt.

## 1. Gate the source

The source is the user's photo: a finished mockup template, or the beginnings of one, perhaps another listing's photo with its design and labels still on. Check two things:

- **Square**: a photo that isn't square is refused, reported to the user, and the run stops. A blank photo must also be exactly 2048 x 2048, which `prepare` checks; cleaning makes any square photo 2048.
- **Blank**: open the photo and look at the whole shirt and the whole frame. List everything that has to go: any print, text, logo, graphic or design on the shirt, and any text or graphic overlay on the photo (a colour-name label, a watermark, a sticker). A design left on the shirt would be recoloured into all 33 photos, and the colour labels arrive at ingestion. A brand label inside the collar is part of the garment and stays.

A blank photo goes straight to step 2. Otherwise tell the user in one line what will be removed, and clean it.

Also note the shirt's current colour. When it already is a palette colour, almost always White, pass `--source-colour White` so the source itself serves as that colour and its brief is skipped.

### Cleaning a source

Remove everything the check listed, and loop until the cleaned photo passes. Work in `C:\Users\Admin\Downloads\mockup-recolours\cleanup-<scene-slug>-<YYYY-MM-DD>\`, with the photo copied in as `original.<ext>`.

1. Write `brief.md` from [cleanup-brief.md](cleanup-brief.md): `{removals}` is a bulleted list of each item and where it is ("the "IVORY" label in the top-left corner, white box included"; "the printed design on the shirt's chest, four candy apples with bows"), `{output}` is `out\generated.png`. Launch one Codex delegate on it, as in step 2.
2. Composite and check it:

   ```sh
   uv run python .claude/skills/create-mockup-template-cc1717/recolour.py clean ORIGINAL GENERATED --out-dir CLEAN_DIR
   ```

   It upscales the generated photo, finds each area the generator edited, and blends only those areas onto the original, as convex patches (so no patch edge traces the removed item) with their tone matched seamlessly at the edge and their grain topped up to the fabric around them. Everything else stays the original's pixels. It writes `cleaned.png` and, per patch, `clean-patch-N.jpg`: original, cleaned, and cleaned at contrast x4. It exits non-zero when a patch fails: **echo**, the generator left the item's edges in place; **grain-vs-shape**, the patch's texture traces the item, the faint shadow of a removed design; or a grain level far from the original's.
3. Open every `clean-patch-N.jpg` and look for anything of the removed items: a tint, an outline, a fleck, a shape in the x4 view. Then look at `cleaned.png` whole for anything else the edit disturbed.
4. On any failure, append a `## Review` section to `brief.md` naming what remains and where, relaunch the delegate, and repeat from step 2. After three failed rounds, stop and show the user the patch reviews.

The passing `cleaned.png` is the source for the rest of the run: check it is blank, as above, before preparing.

## 2. Prepare the run

The scene name is the user's, or the source filename in plain words (`woman holding a bag`). Runs live under `C:\Users\Admin\Downloads\mockup-recolours\<scene-slug>-<YYYY-MM-DD>\`.

```sh
uv run python .claude/skills/create-mockup-template-cc1717/recolour.py prepare SOURCE \
  --scene "woman holding a bag" --run-dir "C:\Users\Admin\Downloads\mockup-recolours\woman-holding-a-bag-2026-11-04" \
  [--source-colour White]
```

It copies the source to `source.png`, writes one brief per colour to generate, `briefs\<colour-slug>.md`, each naming its output `out\<colour-slug>.png`, and prints the two **pilot** briefs: one light colour and one dark (White and Black, or Ivory and Pepper when the source already is one of those).

Every colour is generated the same way: one T3 Code delegate per brief, `delegate_task` with `target: {providerInstanceId: "codex", model: "gpt-6.1-sol", options: {reasoningEffort: "medium"}}`, `mode: "async"`, `role: "design"`, title `Recolour <scene>: <Colour>`, and the task:

> Read the brief at `<brief path>` and follow it. Work only inside `<run dir>`.

Call `orchestrator_capabilities` once first, as T3 requires; if Codex or that model is unavailable, tell the user and stop. Launch a batch in a single response so it runs in parallel, and follow each delegate's completion rather than polling.

## 3. Pilot

A mistake in how the generator reads the photo repeats in every colour, and the drift check can't see a mistake every colour shares. The pilot finds it in two photos instead of thirty-three. You review it yourself; the user is not asked.

Launch the two pilot briefs. When both are back, build the review images:

```sh
uv run python .claude/skills/create-mockup-template-cc1717/recolour.py pilot RUN_DIR
```

It writes `review\pilot\outline.jpg`, the source with the pilot's shirt outline drawn in green, and `review\pilot\tile-*.jpg`, full-resolution tiles over the shirt and its surroundings, each showing the source beside both pilots. Open the outline and every tile. The pilot passes only when each tile shows the pilots matching the source in everything but the shirt's colour:

- **Outline**: the green line follows the shirt's real edge in the source. Sleeves, shoulders, collar and hem neither grow nor shrink; nothing hidden in the source (behind hair, arms, hands or props) becomes visible shirt, and background showing in the source, between hair strands or around the arms, stays background.
- **Everything else**: face, hair, hands, jewellery, other clothing, background and framing are unchanged, not just similar.
- **The shirt**: blank, evenly the pilot colour, its folds and lighting following the source.

On any discrepancy, append a `## Pilot review` section to the brief of each pilot that shows it, describing what is wrong and what the source shows there, in terms of this photo; relaunch those pilots and review again from the `pilot` command. After three failed rounds, stop and report the remaining discrepancies to the user with the tiles that show them.

When both pilots pass, approve them:

```sh
uv run python .claude/skills/create-mockup-template-cc1717/recolour.py pilot RUN_DIR --approve
```

It saves the outline as `garment-reference.png`, which drift is measured against from here on, so a later colour that grows the sleeve is caught. It also copies every `## Pilot review` section into the other briefs, so the remaining colours start with the guidance the pilot needed.

## 4. Generate the rest

Launch every non-pilot brief as one parallel batch. The step is done when every delegate has reported back.

## 5. Assemble and review

```sh
uv run python .claude/skills/create-mockup-template-cc1717/recolour.py assemble RUN_DIR
```

It upscales each `out\` photo 4x with the installed Upscayl app's Standard model (`C:\Program Files\Upscayl`; about 11 seconds a photo, cached in `upscaled\` and rebuilt when a colour is redone), scales it to 2048 x 2048, and composites it: only the inside of the approved shirt outline from step 3 comes from the recolour, blended in over a soft edge, and everything outside the shirt keeps the source's own pixels. It writes those composites to `export\` (with each colour's Text overlay and the `Source Image` reference, which ingestion skips) and tiles them into `review\sheet-NN.jpg`, so the review shows exactly what gets ingested. Each cell shows the target swatch beside a **measured** swatch, the median colour of the shirt area, and a **drift** figure, the percentage of the frame that changed outside the shirt. It exits non-zero listing any colour whose photo is missing or not square, or whose drift is over 1%. Drift must be at most 1%: past that the generator moved the face, hair, jewellery, the shirt's outline or the framing, and the template's calibration won't fit that colour. The script owns the measurement, so take its number as the verdict; it ignores a 16px band around the shirt, where hair strands and edges blend with the new colour, and isolated specks such as a twinkling light. For each colour over the limit it writes `review\drift-<colour>.png`, the recolour with its drift pixels in magenta.

Inside the shirt it checks **shading**: the lighting and the folds must follow the source whatever the colour. It compares the pattern of light and shadow, not the colour, on fabric pixels only (hair lying over the shirt is left out), and against whichever is nearest in brightness, the source or an approved pilot, since dark dye shows folds with more contrast than light. Each colour gets a **lighting** and a **folds** correlation, shown on its sheet cell; it fails below 0.5 lighting or 0.3 folds, which real recolours cleared with room to spare (0.64 and 0.34 at worst) while a relit or flattened shirt scored about 0.1. A failure writes `review\shading-<colour>.png`, the recolour with the mismatched shading in cyan. The check needs the approved pilot, so it starts after step 3.

Retry each listed colour before review. Open its map, append a `## Retry` section to its brief naming the measured figure and what the map shows (a sleeve outline grew, hair shifted, the folds or the light on the shirt changed), and asking that everything but the shirt's colour stay identical to the source; relaunch its delegate. Then re-measure with the quick check, which skips the upscale and export:

```sh
uv run python .claude/skills/create-mockup-template-cc1717/recolour.py drift RUN_DIR
```

Drift is measured against the approved pilot's outline, `garment-reference.png` (without one, against the area most colours changed), and the check re-measures every colour. After three retries of one colour, stop retrying it and flag it, with its map, in the review. Run `assemble` once every colour passes or is flagged.

Open every sheet yourself, then show them to the user, embedded with Markdown image syntax and absolute paths, with the colours worth a closer look: drift well above the rest (the scene, face or framing moved), a measured swatch far from its target, patches of the old colour, or a print that appeared on the shirt. Measured swatches sit darker or lighter than the target where the photo's lighting does; compare them across colours, not to the hex alone. Then ask the user to pick one:

- **redo** named colours, with what is wrong: append a `## Reviewer notes` section with their words to each of those briefs, relaunch only those delegates, and re-run `assemble` and this review;
- **ingest** the set now;
- **stop**, leaving the run directory for later.

## 6. Ingest

On the user's go-ahead, read [ingest-mockup-templates](../ingest-mockup-templates/SKILL.md) and follow it with `RUN_DIR\export` as the source. That skill resolves the workspace, the template directory and the `cc1717-` photo prefix, and owns staging, installation and replacement backups. Finish with its report, plus the run directory and any colours the user accepted with known flaws.
